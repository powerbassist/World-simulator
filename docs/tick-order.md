# The month's tick order

Every game month runs the same systems in the same order, from one place: `WorldMonth` in `src/sim/world_month.gd`. The game, the balance harnesses and the probes all call it, so an order cannot exist in two copies (the reason it was extracted: harnesses that carried their own copy omitted machines and measured a world the game never runs, see [[history]] V4.4 and AGENTS.md "Green is not measured").

The order is load-bearing, not a convenience. The comments at each step in `world_month.gd` say why that step sits where it does (Division first, so a bill the player tabled during the month applies before that close's Economy, Opinion and Elections; Access before Economy, Commodities after Economy and before Opinion, Events after the four registers it reads). When a system is added, the place it goes in this list is a design decision: [[economy-model]], [[opinion-model]] and [[events-model]] record several. The month is also a cursor, so the UI can spread it over frames without changing a byte of the result (V5.1-0a); see [[test-suite-model]] for how the tests hold that.

The diagram below is generated from `STEPS` and checked on every `python tools/check_vault.py`; to update it after adding a step, run `python tools/vault_diagrams.py --write`.
